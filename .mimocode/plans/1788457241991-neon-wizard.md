# Loyallia Wallet Pass Studio -- Full UI/UX Audit Report

## Executive Summary

The Wallet Pass Studio is a **well-architected** visual designer with 10 card types, 50+ components, and a sophisticated state management system. However, there is a **critical disconnect** between what the designer configures and what the preview renders: **40+ visual customization properties** defined in card-type-config types are **completely ignored** by the preview and decoration components. Users who configure stamp shapes, cashback icons, coupon badge styles, etc. will see **NO change** in the preview.

**Overall Grade: B-** (strong architecture, weak visual feedback loop)

---

## CRITICAL ISSUES (Must Fix)

### C1. Visual Customization Gap -- 40+ properties defined but NEVER consumed by preview

Every card type config defines visual properties that are completely ignored:

| Card Type | Unused Visual Properties |
|-----------|------------------------|
| Stamp | `stampShape`, `stampIcon`, `stampFilledIcon`, `stampColor`, `stampGridLayout` |
| Cashback | `coinIcon`, `tierBadge`, `progressRingColor` |
| Coupon | `cutLineStyle`, `discountBadgeStyle`, `offerTag` |
| VIP | `crownIcon`, `memberBadgeStyle`, `benefitsListIcons` |
| Gift | `boxGraphic`, `ribbonColor`, `denominationBadge` |
| Discount | `tierBadgeIcons`, `progressBarColor`, `percentageDisplayStyle` |
| Affiliate | `partnerLogoUrl`, `referralChainIcon`, `ambassadorBadge`, `badgeColor` |
| Corporate | `companyLogoUrl`, `buildingIcon`, `departmentBadge`, `badgeStyle`, `idBadgeColor` |
| Referral | `referralIcon`, `shareButtonColor`, `rewardBadgeIcon`, `friendAvatarPlaceholder` |
| Multipass | `ticketGraphic`, `punchIcon`, `bundleBadgeStyle`, `indicatorStyle` |

**Impact:** Users spend time configuring visual options that have zero effect. This is the #1 source of "nothing works" frustration.

### C2. StampGrid.tsx NOT integrated with preview decorations

`StampGrid.tsx` supports 6 shapes, custom icons, and grid/linear layouts. `StampGridDecoration` in `preview-decorations.tsx` is a completely separate, simpler implementation that only renders circles with check marks. The studio's stamp configuration is disconnected from the preview.

### C3. Hardcoded Spanish strings in data values (not i18n keys)

`VIPTab.tsx` COMMON_PERKS and `GiftTab.tsx` OCCASIONS store Spanish strings as `value` properties that get persisted to config. If UI language changes, stored values remain in Spanish.

### C4. Hardcoded `$` currency symbol

Appears in `CouponTab.tsx` and `GiftTab.tsx`. The project targets Spanish-speaking markets (Ecuador uses `$` but Mexico, Spain use different symbols). Should use tenant-configurable currency.

### C5. No text length validation on ANY field across ALL 10 tabs

Not a single text input has `maxLength` or programmatic length validation. Push notifications have strict character limits (~100-250 chars) but no enforcement exists.

### C6. No required field enforcement

No field in any tab is marked as `required`. Users can save completely empty configurations.

## HIGH PRIORITY ISSUES

### H1. Accent and label colors not applied to preview

ColorsTab exposes 4 color fields (background, foreground, label, accent) but previews only use 2 (background_color, text_color). Label and accent colors have no visual effect.

### H2. Back fields shown on front card (Apple preview)

`AppleWalletCard` renders back fields inline at the bottom of the front card (lines 600-613). Real Apple Wallet back fields are NEVER visible on the front.

### H3. Hardcoded Spanish in preview decorations

5 decoration components have hardcoded Spanish strings: "Valido hasta", "Saldo disponible", "Codigo de afiliado", "sesiones restantes", "referidos".

### H4. stampGridLayout only shows 2 of 5 options

Type supports `'3x3' | '4x4' | '5x2' | '6x2' | 'dynamic'` but UI only offers Grid (hardcoded to `'5x2'`) and Linear (mapped to `'dynamic'`).

### H5. Array fields only accept single icon

`VIPTab.benefitsListIcons` and `DiscountTab.tierBadgeIcons` are typed as `string[]` but UI only allows selecting one icon.

### H6. No cross-field validation

- StampTab: `stampsAtIssue` not validated against `stampsRequired`
- StampTab/CouponTab: start/end dates not validated (start < end)
- DiscountTab: tier thresholds not validated for ascending order
- VIPTab: monthlyFee vs annualFee no consistency check

### H7. No error feedback to user

No tab shows validation errors, warnings, or inline error messages. Invalid input is silently ignored.

### H8. Inconsistent styling across tabs

StampTab and CouponTab use `rounded-md` and `space-y-0.5`; other 8 tabs use `rounded-lg` and `space-y-1`. Suggests different authors/times.

## MEDIUM PRIORITY ISSUES

### M1. No URL validation for URL fields

`AffiliateTab.partnerLogoUrl` and `CorporateTab.companyLogoUrl` accept any string.

### M2. AffiliateTab severely underfeatured

No commission structure, tracking URL, payout threshold, affiliate tiers, cookie duration, or performance metrics. This is the CORE of any affiliate program.

### M3. Missing DATA_MATRIX barcode format in UI

`BarcodeFormat` type includes `'DATA_MATRIX'` but BarcodeTab only shows 4 formats.

### M4. No Apple NFC configuration in AdvancedTab

`AppleSpecificConfig` includes `nfc: NFCConfig` but AdvancedTab does not expose it.

### M5. No Apple expiration date in AdvancedTab

`AppleSpecificConfig` includes `expirationDate` but it's not exposed.

### M6. Drag-and-drop in BackDesignTab is non-functional

Drag handle is rendered but no actual drag-and-drop implementation exists.

### M7. Field visibility cannot be set per-platform

`handleToggleVisibility` sets both `showOnApple` and `showOnGoogle` to the same value.

### M8. Google Wallet preview doesn't differentiate card types

Google Wallet has distinct visual treatments for LoyaltyClass, OfferClass, GiftCardClass. The preview renders all types identically except for decorations.

### M9. No pass state visualization

No visual indication for expired, voided, or inactive passes in preview.

### M10. Color harmony only updates accent color

"Armonia de color" swatches only set `accent` color which is barely visible in preview. Should update `foreground` or whichever color the user last interacted with.

## LOW PRIORITY ISSUES

### L1. Magic numbers for all max constraints

15 different magic numbers across all tabs (e.g., `max={20}` for stamps, `max={999999}` for fees). None defined as constants.

### L2. Missing `data-testid` on some interactive elements

StampTab grid/linear and visit/consumption toggle buttons lack test IDs.

### L3. Duplicate constant definitions

MultipassTab defines `INDICATOR_STYLES` but `bundleBadgeStyle` buttons duplicate values inline.

### L4. Font rendering uses system fonts

Preview uses Tailwind utility classes instead of San Francisco (Apple) / Roboto (Google).

### L5. Barcode is always a static placeholder

No way to see actual encoded barcode with configured message.

### L6. Google back card uses emoji for link icons

Inconsistent with rest of UI's SVG icon approach.

### L7. Icon picker has no upload functionality

`allowUpload` prop exists but only shows hint text.

### L8. Detail images lack dimension inputs

`DetailImage` type has `width`/`height` but UI only shows URL input.

### L9. Color presets not card-type-aware

Presets are generic, not tailored to card types.

### L10. COMMON_PERKS hardcoded Spanish values

VIPTab stores `'Acceso prioritario'`, `'Envio gratis'` etc. as data values instead of i18n keys.

## PER-CARD-TYPE FITNESS ASSESSMENT

### 1. Stamp Card -- Grade: B+
**Good:** stampsRequired, rewardDescription, stampExpiry, stampType (visit/consumption), consumptionPerStamp, birthdayStamps, dailyStampLimit, shape/color/icon selection.
**Missing:** Structured reward type, multiple/milestone rewards, terms & conditions.
**Bug:** stampGridLayout only exposes 2 of 5 options.

### 2. Cashback -- Grade: B
**Good:** cashbackPercentage, minimumPurchase, creditExpiryDays, tierName, progressRingColor.
**Missing:** Maximum cashback cap, currency denomination, accumulation rules, redemption rules, earning tiers.

### 3. Coupon -- Grade: B+
**Good:** discountType, discountValue, usageLimitPerCustomer, couponDescription, pushMessage, promoText, expiry, dates, cutLineStyle, badgeStyle, offerTag.
**Missing:** Minimum purchase, applicable products, stackability, coupon code, max discount cap.
**Bug:** Hardcoded `$` currency.

### 4. VIP Membership -- Grade: B-
**Good:** membershipName, monthlyFee, annualFee, validityPeriod, perks (custom + common), crownIcon, badgeStyle.
**Missing:** Tier progression, enrollment requirements, member since date, renewal rules.
**Bug:** benefitsListIcons only accepts 1 icon (type is `string[]`).

### 5. Gift Certificate -- Grade: B
**Good:** denominations, expiryDays, occasion, ribbonColor, boxGraphic, denominationBadge.
**Missing:** Custom amount option, sender/recipient message, balance tracking, transferability.
**Bug:** Hardcoded `$` currency, OCCASIONS stored as Spanish strings.

### 6. Tiered Discount -- Grade: B+
**Good:** tiers (name/threshold/percentage), bannerText, progressBarColor, displayStyle, tierBadgeIcon.
**Missing:** Tier reset period, progress tracking rules, tier benefits description.
**Bug:** tierBadgeIcons only accepts 1 icon.

### 7. Affiliate -- Grade: D
**Good:** affiliateCodePattern, benefitsDescription, partnerLogoUrl, badgeColor, referralBannerText.
**Missing:** Commission structure (CORE feature), tracking URL, payout threshold, affiliate tiers, cookie duration, performance metrics, partner name.
**Verdict:** Severely underfeatured for a real affiliate program.

### 8. Corporate Discount -- Grade: B
**Good:** companyName, corporateDiscountPercentage, employeeIdRequired, companyLogoUrl, badgeStyle, securitySeal.
**Missing:** Employee list/bulk enrollment, department-specific discounts, validity period, usage limits, minimum purchase.

### 9. Referral Pass -- Grade: B-
**Good:** referrerReward, refereeReward, maxReferralsPerCustomer, referralCodePattern, shareButtonColor.
**Missing:** Structured reward types, attribution window, qualifying action, tiered rewards, share channels config.

### 10. Multipass -- Grade: B
**Good:** bundleSize, bundlePrice, passTypeLabel, ticketGraphic, punchIcon, bundleBadgeStyle, indicatorStyle.
**Missing:** Individual pass value, validity period, transferability, usage restrictions.

2. Integrate `StampGrid.tsx` into `StampGridDecoration` instead of the separate circle-only implementation
3. Add `maxLength` to all text inputs (push messages: 200, names: 100, descriptions: 500)
4. Add `required` markers to essential fields (stampsRequired, rewardDescription, discountValue, membershipName, etc.)
5. Replace hardcoded `$` with tenant currency setting
6. Fix hardcoded Spanish in VIPTab COMMON_PERKS and GiftTab OCCASIONS
