# Fix Plan — TypeScript Errors, Test Failures, and UI/UX Audit

## Context
We made ~30 changes across 26 files for the UX/UI loyalty card improvement plan. The typecheck has 14 TypeScript errors and the unit test suite has 14 test failures (plus 1 pre-existing). This plan fixes every error, then runs full Playwright E2E tests to verify all flows.

## PART 1: TypeScript Error Fixes (14 errors)

### 1.1 `templates/registry.ts` — missing `creditExpiryType` (ALREADY FIXED in build mode)
3 cashback template configs were missing `creditExpiryType`. Fixed by adding `creditExpiryType: 'defined_period' as const` to lines ~79, ~525, ~860.

### 1.2 `programs/new/page.tsx` — "Object is possibly 'undefined'" (5 errors)
Lines 115, 242, 243, 282, 283 — `CARD_TYPE_LABEL_KEYS[form.card_type]` can be undefined.

**Fix:** Add non-null assertion `!` where we know the key exists (all 10 card types have entries), OR add a guard:
```ts
const keys = CARD_TYPE_LABEL_KEYS[form.card_type];
if (!keys) return null; // or fallback
```
At each call site use `keys.labelKey` / `keys.descKey`.

### 1.3 `ProgramReviewStep.tsx` — unused `BARCODE_TYPES` import
Line 3: `import { CardTypeIcon, BARCODE_TYPES, BARCODE_TYPE_LABEL_KEYS, CARD_TYPE_LABEL_KEYS }` — `BARCODE_TYPES` no longer used since we switched to `BARCODE_TYPE_LABEL_KEYS`.

**Fix:** Remove `BARCODE_TYPES` from import.

### 1.4 `ProgramReviewStep.tsx` — "Object is possibly 'undefined'" line 177
`t(CARD_TYPE_LABEL_KEYS[selectedType?.value ?? 'stamp'].labelKey)` — `CARD_TYPE_LABEL_KEYS[...]` can be undefined.

**Fix:** Add non-null assertion or guard.

### 1.5 `WalletCardPreview.tsx` — unused `CARD_TYPES` import
Line 4: `CARD_TYPES` no longer used since we changed `typeof CARD_TYPES[0]` to `{ value: string; icon: string }`.

**Fix:** Remove `CARD_TYPES` from import.

### 1.6 `GoogleWalletPreview.tsx` — "Object is possibly 'undefined'" line 365
`t(CARD_TYPE_LABEL_KEYS[selectedType?.value ?? 'stamp'].labelKey)` — same pattern.

**Fix:** Add non-null assertion or guard.

### 1.7 `ColorsTab.tsx` — "Type 'string | undefined'" line 390
`centralBackground` is optional in `WalletColors` but `ColorInput` expects `value: string`.

**Fix:** Use `colors.centralBackground ?? ''` when passing to `ColorInput`.

### 1.8 `StudioCanvas.tsx` — unused `t` variable line 166
`buildSelectedType` accepts `t` parameter but no longer uses it after we removed `t(key)`.

**Fix:** Remove `t` from function signature (line 166: `buildSelectedType(state: WalletPassStudioState, t: ...)` → `buildSelectedType(state: WalletPassStudioState)`) and remove `, t` from call site (line 176).

### 1.9 `useDesignScore.ts` — "Object is possibly 'undefined'" line 40
```ts
function isDefaultColor(key: keyof typeof DEFAULT_COLORS, value: string): boolean {
  return DEFAULT_COLORS[key].toLowerCase() === value.toLowerCase();
}
```
`DEFAULT_COLORS[key]` can be `undefined` because `centralBackground` is optional in `WalletColors`.

**Fix:** Add nullish coalescing: `return (DEFAULT_COLORS[key] ?? '').toLowerCase() === value.toLowerCase();`

## PART 2: Unit Test Fixes (14 failures)

### 2.1 `ColorsTab.test.tsx` — 13 failures
**Root cause:** `createMockColors()` creates `WalletColors` without `centralBackground`. When `ColorsTab` renders `ColorInput` for the new 5th field, `value` is `undefined`, crashing at `value.toUpperCase()`.

**Fix:** Add `centralBackground: ''` to `createMockColors()`:
```ts
function createMockColors(overrides: Partial<WalletColors> = {}): WalletColors {
  return {
    background: '#1A1A1A',
    foreground: '#FFFFFF',
    label: '#9CA3AF',
    accent: '#3B82F6',
    centralBackground: '',
    ...overrides,
  };
}
```
Also update test `'renders all 4 color input labels'` → `'renders all 5 color input labels'` and add `expect(screen.getByText('Fondo central')).toBeDefined()`.

### 2.2 `BackDesignTab.test.tsx` — 1 failure (line 140-149)
**Root cause:** The test clicks `checkboxes[0]` expecting "Sitio Web" quick link, but now the first checkbox is from the new Card Information section ("Términos de uso").

**Fix:** Update the test to find the correct checkbox by label text instead of index:
```ts
const sitioWebCheckbox = screen.getByLabelText('Sitio Web');
```
Or adjust the index to account for the 13 new Card Info checkboxes.
