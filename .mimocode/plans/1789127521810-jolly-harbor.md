# Settings Architecture: Django Settings as Single Source of Truth

## Current Problem

Settings are scattered across 4 layers with no clear ownership:

| Layer | Where | Problem |
|---|---|---|
| `.env` file | `docker-compose.yml` env vars | Secrets in files, not Vault |
| Vault | `secret/data/loyallia/{mode}` | Credentials only, not runtime config |
| `PlatformSetting` model | DB + Redis cache | Some settings, not all |
| Django settings | `base.py`, `development.py`, `production.py` | Hardcoded defaults, env var fallbacks |

**Result:** No single place to see/change all settings. Some settings require code changes, some require DB changes, some require env var changes.

## Target Architecture

**One source of truth: Django settings + PlatformSetting model**

| What | Where | How to Change |
|---|---|---|
| Secrets (API keys, passwords, certificates) | Vault | SuperAdmin → Integrations tab |
| Runtime config (URLs, limits, toggles) | PlatformSetting model | SuperAdmin → Settings tabs |
| System constants (timeouts, sizes, defaults) | Django settings | Code change (rare) |

**No .env secrets. No env var secrets. Only system-level parameters.**

## Phase 1: Move all .env secrets to Vault

**Files to modify:**
- `docker-compose.yml` — Remove secret env vars, keep only system params
- `.env` — Keep only `COMPOSE_PROJECT_NAME`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` (Docker needs these)
- `backend/loyallia/settings/base.py` — Read all secrets from Vault, not env vars

**Current .env secrets that must move to Vault:**
| Current .env Key | Vault Key | Status |
|---|---|---|
| `PUBLIC_BASE_URL` | `public_base_url` (PlatformSetting) | Already in PlatformSetting |
| `NEXT_PUBLIC_API_URL` | N/A (frontend build arg) | Keep as build arg |
| `NEXT_PUBLIC_APP_URL` | N/A (frontend build arg) | Keep as build arg |

**Django settings that read from env vars (must change to Vault/PlatformSetting):**

|---|---|---|
| `SECRET_KEY` | `get_secret("secret_key")` | Already Vault ✓ |

| `REDIS_URL` | `get_secret("redis_url")` | Already Vault ✓ |
| `MINIO_ENDPOINT` | `config("MINIO_ENDPOINT")` | Keep env (system param, not secret) |

## Phase 3: Frontend settings from API, not env vars

**Current:** Frontend reads `NEXT_PUBLIC_*` env vars at build time.
**Target:** Frontend reads settings from API at runtime.

**Changes:**
- `frontend/src/lib/constants.ts` — Read settings from API, not `process.env`
- `frontend/next.config.js` — Keep only build-time settings (API URL)
- Add `/api/v1/platform/config/` endpoint that returns public settings

---

## Phase 4: Development vs Production switching

**Current:** `DJANGO_SETTINGS_MODULE` defaults to `development` in docker-compose.yml.
**Target:** Single switch in PlatformSetting `PLATFORM_MODE`.

**Changes:**
- `docker-compose.yml` — Remove `DJANGO_SETTINGS_MODULE` override
- `base.py` — Read `PLATFORM_MODE` from PlatformSetting, apply dev/prod overrides at runtime
- `development.py` / `production.py` — Merge into `base.py` with conditional logic
